# v0.0.21 work in progress — 2026-09-26

## Done and verified on the Android 15 emulator

### Apple-style R corners
- Removed the global `body * { border-radius: 14px !important }` rule. It rounded
  full-screen layers (the screen corners), turned one-sided accent borders into
  brackets and forced radio buttons and slider thumbs into squares.
- One circular-arc scale in `globals.css`: 6 / 10 / 14 / 22 / 28 / 34 px plus the
  999 px capsule. No `corner-shape` anywhere.
- Tailwind (`DEFAULT`, `2xl`, `3xl`, `full`), Mantine (`xl` is the capsule) and MUI
  radii all resolve to that scale; Button/ActionIcon/SegmentedControl/Avatar default
  to capsule/circle, Checkbox to 6 px. Fixed `Textarea: TextInput.extend`.
- iOS shape roles: capsule tab bar with a concentric capsule lens, circular header
  and composer icon buttons, capsule primary buttons and chips, 22 px cards and
  grouped lists, 34 px sheets that float 8 px inside the display edges.
- 22-page corner audit (`.cache/tools/tour.sh`): no square boxes, no rounded
  screen-edge layers, no one-sided bracket borders. Theme swatches are clipped by
  their rounded preview and are expected.

### Liquid glass
- Android Auto now resolves to Balanced (was Reduced: no glass at all).
- Real blur only on floating chrome (header controls, tab bar, composer, mode bar,
  menus, sheets, tooltips). Scrolling content is never blurred and there is no
  glass-on-glass; this is what multiplied composited layers during streaming.
- Content surfaces use a translucent glass sheet with a specular sheen over new
  ambient colour washes in the environment (light and dark).
- iOS scroll-edge fades under the header and tab bar (disabled on the Live2D stage
  and with custom photos). Reduced quality keeps chrome nearly opaque.
- Streaming a long mock reply (code block, table, list): 0 tile-memory warnings.

### Tile memory warnings
- A blank one-paragraph control page served in the same WebView also logs 2–4
  `tile memory limits exceeded` lines on cold start, so the startup lines come
  from WebView before its first draw, not from the app UI.

### Live2D
- Root cause: `.gitattributes` forced `* text eol=lf`, so committing `model.moc3`
  rewrote its 36 CRLF byte pairs (7,427,136 → 7,427,100 bytes). v0.0.19 was built
  from an unaffected working copy; v0.0.20 was built from the damaged blob.
- Restored the original `model.moc3` from the official v0.0.19 APK
  (sha256 `5b669ba90aa97ed9…`). Cubism Core creates it: 796 parameters, 409 drawables.
- The Cubism 5.3 Core added in v0.0.20 moved `drawables.renderOrders` to the model,
  so the Cubism 4 renderer inside pixi-live2d-display drew nothing. Restored the
  v0.0.19 Core (Cubism Core 5.0.0, supports MOC 3.0–5.0). The model renders.
- Removed the pre-load probe that downloaded the 7.4 MB moc a second time. A failed
  load now reads only the first chunk of the moc and compares it with
  `csmGetLatestMocVersion()`; error texts no longer tell users to use Cubism 4.
- `.gitattributes` now uses `text=auto` with an explicit binary list.

- `live-web.sh [--no-build] [--persist]`: builds the Android renderer bundle and
  serves it to the installed debug app through `WebView.setServerBasePath`.
- `cdp.mjs eval|shot|layers`: DevTools Protocol against the app WebView.
- `tour.sh <label>`: screenshots and corner audit for every main page.
- `mock-llm.mjs`: OpenAI-compatible mock on port 18080 (`adb reverse tcp:18080 tcp:18080`).
- Emulator `Yachiyo_API35`: the debug app has a persisted dev bundle path and an
  OpenAI provider pointed at the mock with a placeholder key.
