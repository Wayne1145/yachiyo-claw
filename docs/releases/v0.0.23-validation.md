# v0.0.23 validation

## Reproduced and fixed

- MuMu DeepSeek `deepseek-flash`, configured by the user as a custom provider,
  returned HTTP 400: `Thinking mode does not support this tool_choice`.
  The compatibility fix changes forced `required` to `auto` and preserves
  assistant `reasoning_content`. Real ordinary chat returned the requested
  text. Two real Agent model requests returned 200, executed `sandbox_bash`
  with an explicit approval and completed through `agent_complete`.
- The user's long Tetris conversation had a 506,733-character assistant record.
  Instrumented IndexedDB writes showed a new assistant placeholder increasing
  the message count from 5 to 6, then `ResultPersister.flushTaskSessionUpdates`
  replacing it with an old 5-message snapshot. Model/tool requests continued
  invisibly. Atomic functional updates fix this race. The same conversation
  subsequently retained its seventh message (16 content parts), completed a
  follow-up check and survived application restart and chat/Agent switching.
- Alpine and Ubuntu both produced correct Python/Node/Git output but were marked
  exit 126. Removing a racy `/proc` disappearance check allows `Process.waitFor`
  to report the real exit code. Repeated real checks returned exit 0 and empty
  stderr; Ubuntu's independent job was `succeeded`.
- Plugin lifecycle depended on the translation function identity. A language
  update could abort queued/live actions. The new regression covers an in-flight
  action during a language change; committed state is available before clicks.

## MuMu observations

- Test package uses x86_64 on MuMu. An arm64-translated install had caused guest
  runtime failures; that is not evidence of arm64 hardware failure or performance.
- User and agent acceptance generated a Tetris site through real model/tool calls.
  Independent ADB-forwarded HTTP verification returned 200 for the generated
  local port 8080 page. The user's separate long conversation also generated
  and deployed its project. Generated-model claims about game tests are not
  counted as independently executed host tests here.
- Model catalog download, unified queue, installed-model listing and preloading
  worked for SmolLM2-135M Q4_K_M (~101 MB). Native PSS was ~212 MB after load.
  Two ordinary-chat turns produced actual local output; the second emitted five
  native token deltas. Navigating to Live2D during generation retained the result.
  Approximate first-token delay was 28 seconds on this emulator with its full
  conversation prompt; no claim that local latency is fully optimized.
- ADB screenshots personally inspected at 1200x2608 and 1440x3200 portrait:
  chat/Agent shared composer layout, visible Live2D, reachable interactive
  settings and model controls. Settings, downloads, tasks and local models
  rendered without horizontal document overflow in the tested viewports.

## Android compatibility smoke

- Android 11: installed debug build, settings/general/chat/local-model/download/
  tasks pages rendered without horizontal overflow or React error UI. Release
  APK then installed over the debug build and launched with versionCode 23 and
  no Android DEBUGGABLE flag. This device had no provider credentials; interactive
  navigation reached onboarding, not a validated model interaction.
- Android 13: debug install and the same route checks plus the development page
  passed at 393 CSS pixels wide. Existing local-model configuration remained
  visible. No credentials were copied from MuMu to these clean smoke devices.
- Android 15: the same route checks passed, followed by installation and launch
  of the signed release APK. Settings/downloads/tasks/development showed no
  horizontal document overflow. Interactive onboarding remains explicitly outside
  a real-model interaction test on this credential-free device.
- The additional SDK emulators initially failed to expose ADB while sharing
  MuMu's server. A separate workspace ADB server on port 5041 restored connection;
  the successful checks above were run afterward, not inferred from boot logs.

## Scope limits

- This is targeted release acceptance, not proof that every third-party model,
  MCP/Skill/plugin, root manager or physical phone works.
- Large 4B/7B GGUF performance, GPU/NPU tuning, physical microphone/camera quality,
  every background permission combination and real app-store distribution remain
  outside this emulator pass.
- Android force-stop / package replacement terminates background processes;
  the model's inference that a restarted server failed merely from crossing a
  conversation turn is not established by these observations.
- Full public-GitHub automatic download-to-install UI is distinct from the APK
  signature/upgrade checks. It is not claimed covered by an ADB install alone.

Raw screenshots, diagnostic scripts and logs are retained in ignored `.cache/`;
API keys and conversation dumps are not included in the repository.
